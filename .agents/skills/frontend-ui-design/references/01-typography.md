# 01 — Typography

## Purpose
Typography should make reading order obvious at a glance. Good hierarchy is not simply about making the headline large; it is about using a coherent scale and balancing size, weight, line-height, contrast, spacing, and placement.

## Reference hierarchy
A useful mobile/card reference from training:
- Headline: ~24 px
- Subheadline: ~16 px
- Body: ~14 px
- Button text: ~16 px

These are references, not universal values. Adapt to platform, font metrics, density, and accessibility.

## Good vs bad type hierarchy
Good typography:
- clear headline > subheadline > body order
- coherent jumps between sizes
- comfortable body size and line-height
- button text proportionate to the control
- repeated text roles across the product

Bad typography often comes from:
- oversized buttons relative to the rest of the UI
- tiny body copy
- arbitrary font sizes
- weak line-height
- too many unrelated weights/sizes
- decorative fonts used in functional UI

## Expressive/display-font reference set
These fonts were learned as stylistic references for branding and display use:

- **Richter** — futuristic, geometric, techno, experimental
- **Orcish** — playful, organic, retro, expressive
- **Mageline** — elegant, editorial, fashion/luxury serif
- **Wisteriano** — decorative, artistic, premium/luxury
- **Bevorden** — bold, condensed, sporty, street/tech

### Use them for
- logos
- hero headings
- posters
- campaign graphics
- expressive section titles
- brand marks

### Do not default to them for
- body copy
- forms
- dense dashboards
- data tables
- navigation
- settings

Functional UI normally needs neutral, highly readable type unless the product calls for something more expressive.

## Typography principles
1. Fewer text styles are usually better than many arbitrary ones.
2. Use semantic text tokens: display, h1, h2, body, small, caption, button, label.
3. Body copy should never be made too small just to fit more content.
4. Hierarchy should survive without color; size/weight/spacing must still communicate structure.
5. Keep line lengths readable, especially for supporting copy.
6. Use stronger type only where priority requires it.
7. Match type personality to the product domain.

## Product-fit examples
- Luxury/editorial: serif display + restrained sans body
- SaaS/enterprise: clean sans with strong numerical readability
- Sport/gaming: expressive display face for branding, neutral UI font for controls
- Government/HRIS: conservative, highly readable sans with disciplined hierarchy

## Rule of thumb
> Use expressive typography for identity; use readable typography for work.
